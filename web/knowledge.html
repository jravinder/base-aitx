How Base Brain is built

Public sources go into one database. The ask server answers from it in a fixed order. Pages read small JSON files, so they work without the server.

Answers in a fixed order

Where answers show

Pages read files in web/data/.

  • Member pagePOST /learn/log when the server runs
  • Base Brain, this pagekb_graph.json, faq.json, learning.json
  • Admin, approve or reject proposalsPOST /learn/approve, /learn/reject
↺

The loop back. Every question goes to data/live/questions.jsonl. Each night store/learn.py groups them and proposes a template, a cached answer or a route to Base support. After a person approves, the answer becomes a learned_answer entry in the knowledge base. Nothing goes live without approval. Source: LEARNING.md, KNOWLEDGE_BASE.md.

How an answer is made

One question, start to finish.

  1. 1Question

    A member types it on Help, Ask or the member page.

  2. 2Search entries

    Recorded answers, Base policy, the knowledge base, templates, then the agent.

  3. 3Answer with sources

    Each number gets a [n] tag. The critic checks each number is in the result.

  4. 4Logged

    One line in questions.jsonl. Emails, phone numbers and street addresses are removed.

  5. 5Reviewed

    store/learn.py proposes each night. A person approves or rejects on Admin.

  6. 6New entry

    An approved answer goes to brain/insights.json and the knowledge base.

How data gets in

Collectors on the Mac, one database in the middle, small files out to the pages. Full lineage: Data lineage.

  1. 1Collectors

    launchd jobs: hourly, daily, monthly.

  2. 2Raw files

    data/live/, data/mirror/, faq/corpus/.

  3. 3fleet.db

    store/build.py loads each file with natural keys.

  4. 4Build

    store/kb.py, store/faq.py, store/learn.py, store/signals.py, admin/build.py.

  5. 5Pages

    JSON in web/data/ and data/. Pages read only these files.
